# ShenZhi Web 协作规则

本文件适用于 `apps/web/`。同时遵循仓库根目录的 `AGENTS.md`。

## 前端约束

- `app/` 负责 Next.js 路由、页面入口和页面组合；复杂界面、状态与业务逻辑放入对应的 `features/{module}/`。
- 页面与组件通过现有 `clients/` 调用后端或外部服务；Feature 内确有业务编排时，再在该 Feature 中建立 Service。
- `app/api/` 仅承载认证、Web 框架相关接口和必要的 BFF 能力，不在其中扩展系统核心业务 API。
- 科研能力和第三方服务不得直接绑定页面或组件，不在各处散落重复的请求逻辑。
- Feature 内的组件、Hook、类型和常量优先留在 Feature 内；确认被多个业务模块复用后，再提升为全局公共代码。
- 子功能在 `app/` 与 `features/` 中保持一致的业务语义，但不要求目录严格镜像。
- 除已有的 Next.js 框架级能力外，页面和普通业务组件不得直接访问数据库。
- 沿用现有组件体系、样式方案、类型定义和依赖；不机械创建没有独立职责的 Service、Hook、类型或目录。
- 修改完成后，使用仓库已有脚本执行与改动范围相符的 lint、类型检查、测试或构建验证。

如需改变前端分层或新增全局公共能力，先确认现有位置不能承载该职责。
