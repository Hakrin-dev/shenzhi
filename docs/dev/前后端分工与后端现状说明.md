```text
浏览器 React
  ├─ /api/auth/*     → Better Auth + PostgreSQL
  └─ /api/v1/*       → apps/web/services/backend/forward.ts
                         ↓ BUSINESS_BACKEND_URL
                    apps/backend/app/main.py（FastAPI 占位 SSE）
```

| 路径 | 状态 |
| --- | --- |
| `apps/web/features/search/`、`agents/ask/` | ✅ A 前端 |
| `apps/web/lib/api/`、`lib/ask/` | ✅ 正式契约客户端 |
| `apps/web/services/backend/forward.ts` | ✅ 身份头转发 |

本地联调见 [前后端通信架构.md](./前后端通信架构.md)；一键启动：仓库根目录 **`启动.bat`**（FastAPI 8000 + Next 3000）。

## 六、两条线如何合并（建议）

1. **目录：** 以 `dev` 的 `apps/web` 为准，把 B 分支的 `app/api/ai/chat`、C 的 uploads/web-search **迁入** `apps/web/app/api/` 或 **下沉到** `apps/backend`（与架构文档一致时选后者）。
2. **认证：** 保留 `dev` 的 Better Auth；**不要**把 B 分支 NextAuth/Prisma SQLite 直接覆盖。
3. **模型：** 将 B 分支 `createModelStream()` / DeepSeek 逻辑迁入 **FastAPI**，Next 只保留 BFF；或短期在 `apps/web` 保留 `/api/ai/chat` 作过渡。
4. **A 前端：** `dev` 已含 A；B 分支的 composer/store/C  provider 需按路径合并到 `apps/web/features/`。
5. **验收：** 合并后以 `docs/dev/AI搜索-开发文档.md` 的 `/api/v1` 包络为准做回归。
